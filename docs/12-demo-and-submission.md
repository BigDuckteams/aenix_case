# 12. Финальное демо и сдача

## 1. Сценарий демо (≈ 7 минут)

Требование кейса: показать полный путь на одном примере — **загрузка → визуализация → изменение → генерация Java → запуск → сравнение поведения** («Монолит → Граф → Диагноз → Улучшение → Тесты»).

Пример для демо: `samples/demo-orders` (≈1000 строк, сгенерирован ИИ и проверен, как у организаторов). Перед демо — чистая БД (`JB_SEED_DEMO=0`), загрузка с нуля.

| № | Шаг | Что говорим и показываем | Время | Критерий оценки |
|---|---|---|---|---|
| 1 | **Монолит.** Загрузить `Main.java` (drag-and-drop) | «Один файл на ~1000 строк: разбор, анализ, оптимизация, вывод». Дерево «Проект», LOC, метрики | 0:30 | Java scope |
| 2 | **Запуск оригинала.** «Запуск» со stdin | Кириллица во вводе и выводе; консоль: «Компиляция успешна ✓»; код выхода и время | 0:30 | Сохранение поведения |
| 3 | **Граф.** Открыть `processOrders` | Блок-схема: переменная, условие с Да/Нет, цикл for each как контейнер, вызов метода. Клик по блоку → подсветка строк, курсор в коде → выделение блока | 0:45 | Понятность интерфейса |
| 4 | **Диагноз.** Вкладка «Проблемы» | Вложенный цикл O(n²), длинный метод, дублирование. Карточка: строка, узел, объяснение, сложность, исправление, эффект. «Проверить»: счётчики на графе, график роста (k≈2) | 1:15 | Диагностика |
| 5 | **Правка графа → код.** Изменить условие в инспекторе, добавить блок «Операция» из палитры | Код в Monaco обновился, форматирование сохранено; undo/redo | 0:45 | Java ↔ граф |
| 6 | **Правка кода → граф.** Поменять строку в Monaco | Граф обновился ≤ 1 с; при синтаксической ошибке — баннер | 0:30 | Java ↔ граф |
| 7 | **Тесты — эталон.** «Сгенерировать сценарии» | 12 сценариев, покрытие 87%; непокрытые узлы серые; «Записать эталон» | 0:45 | Сохранение поведения |
| 8 | **Улучшение.** «Оптимизировать» | План: шаги с эффектом; применение по одному, gate после каждого; итог O(n²) → O(n log n), ускорение «до 5.2×» (измерено) | 1:00 | Оптимизация |
| 9 | **Декомпозиция.** Вкладка «Декомпозиция» | Монолит → `Parser`, `Analyzer`, `Optimizer`, `Main`; перенос метода между карточками; «Применить» | 1:00 | Декомпозиция |
| 10 | **Проверка поведения.** Gate | Сборка → 12 из 12 сценариев → «Поведение совпадает ✓»; «Дебаг» показывает покрытие | 0:30 | Контракт кейса |
| 11 | **Негативный контроль.** Внести `+` → `-` | Gate краснеет, diff; откат undo → снова зелёный | 0:30 | Качество проверки |
| 12 | **Экспорт.** «Экспорт Java», отчёт | Архив компилируется `javac` вне инструмента | 0:15 | Сдача |

**Запасной план:** 1) весь путь записан на видео (экран, 3–4 мин) и лежит в репозитории; 2) в приложении есть предзагруженный проект «demo-orders (готовый)» с уже сгенерированными сценариями; 3) на втором ноутбуке поднят `docker compose` с тем же состоянием.

## 2. Вопросы жюри и ответы

| Вопрос | Ответ |
|---|---|
| Как гарантируется сохранение поведения? | Gate: компиляция + прогон всех сценариев против эталона (stdout, stderr, код выхода, исключения). Автопреобразования не применяются, если gate красный. Негативный контроль в демо. Покрытие показывается, слабая проверка помечается |
| Что если сценариев мало? | Генератор строит их по схеме ввода и покрытию узлов; можно добавлять вручную и импортировать |
| Чем вы разбираете Java? | tree-sitter-java; код правится точечно по диапазонам, поэтому форматирование и комментарии сохраняются |
| Зачем нет LLM? | Детерминизм и воспроизводимость: одинаковый вход — одинаковый результат; всё объяснимо и проверяется gate |
| Насколько точна оценка Big O? | Статическая модель стоимости с каталогом JDK и эвристиками; уверенность помечена; динамическая проверка подтверждает показателем роста |
| Что вне рамок? | Потоки, рефлексия, файлы/NIO, сеть, `java.time` — код с ними сохраняется и запускается, но не анализируется (блок «Код») |
| Масштаб? | Один процесс, однопользовательский; цель — монолиты ≈1000 строк |
