# S1. Контракт API и корпус примеров

**Часы:** H2–6 · **Треки:** A, B, C · **Веха:** M0

## Цель

1. Зафиксировать контракт между frontend и backend до реализации (contract-first), чтобы S3 и S4 шли параллельно.
2. Создать корпус Java-примеров: демо-монолит на ≈1000 строк и фикстуры scope. Без корпуса нечем проверять S2–S9.

## Зависимости

S0.2–S0.5 (скелеты и генерация типов).

## Задачи

| ID | Задача | Трек | Ч | Результат |
|---|---|---|---|---|
| S1.1 | Pydantic-схемы по [08](../08-api.md): `SourceRange`, `FlowNode/Edge/Graph`, `StructureGraph`, операции (`ops`), `Finding`, `Fix*`, `DecomposePlan`, `Scenario`, `Run*`, `SSE`-события, `ApiError`; заглушки роутеров с `501` или моковыми ответами | B + A | 1,5 | OpenAPI содержит все эндпоинты и схемы |
| S1.2 | `pnpm gen:api` → `schema.d.ts`; моки frontend: JSON-фикстуры ответов (`structure`, `flow` на 15–20 узлов с циклом/условием/вызовом, `findings`, `scenarios`, `run events`) и режим `NEXT_PUBLIC_MOCK=1` | C | 1 | Frontend запускается и работает на моках |
| S1.3 | **Демо-монолит `samples/demo-orders/Main.java`** (≈1000 строк): ввод через `Scanner` (кириллица), парсинг команд, валидация, анализ заказов, «оптимизируемые» участки, вывод через `printf`; содержит заведомо: вложенный цикл поиска/слияния (как на слайде 5), `contains` по `ArrayList` в цикле, конкатенацию строк в цикле, `==` для строк, пустой `catch`, длинный метод (≥ 40 строк), дублирование (2–3 клона), god-class с ролями parse/analyze/optimize/print, собственные исключения, `record`/`enum`/дженерик-метод/лямбды/Stream. Детерминированный вывод | A | 2 | Компилируется, запускается, вывод стабилен |
| S1.4 | Сценарии для демо: `samples/demo-orders/scenarios/*.json` (≥ 8 ручных: пустой ввод, один заказ, много заказов, неверный формат, исключение, кириллица, граничные значения, большой ввод) | A | 0,5 | Сценарии прогоняются `scripts/verify_corpus.py` |
| S1.5 | Пример слайда 5: `samples/analyzer-pairs/Analyzer.java` + сценарии | A | 0,25 | Компилируется, вывод стабилен |
| S1.6 | Фикстуры scope: по одной минимальной программе на строку таблицы [04 § 9](../04-code-graph-model.md#9-покрытие-java-scope) (разделы 1–4 и бонус) + `expected_kinds.json` и ≥ 2 сценария; первый проход — по одной фикстуре на раздел/конструкцию, дальше по ходу S2 | A | 2 | `samples/scope/*` покрывает все строки таблицы (разделы 1–4 — к H6, бонус — к H12) |
| S1.7 | Дополнительные монолиты `samples/monoliths/` (4–6 штук, 600–1200 строк): сгенерировать ИИ, прогнать `javac`, проверить вывод вручную; разные темы (текстовый анализ, инвентарь, матрицы, граф, парсер выражений, банк) | A | 1,5 | Минимум 3 к H12, остальные к H24 |
| S1.8 | `scripts/verify_corpus.py`: для каждого примера `javac` + прогон сценариев ×2 → проверка детерминизма (I4, I5), отчёт | B | 0,75 | Скрипт зелёный на текущем корпусе |
| S1.9 | `samples/broken/` и `samples/out-of-scope/` — по 2–3 файла | A | 0,25 | Файлы есть, описаны в README каталога |

Корпус генерируется ИИ (как делают организаторы), **но каждый файл проверяется**: компиляция, повторяемый вывод, отсутствие конструкций вне рамок (кроме папки `out-of-scope`).

## Артефакты

- `backend/app/schemas/*` и актуальный OpenAPI; `frontend/src/lib/api/schema.d.ts`; моки.
- `samples/` (демо, scope, монолиты, сломанные, вне рамок) + `scripts/verify_corpus.py`.

## Критерии выхода

- [ ] OpenAPI покрывает все эндпоинты [08](../08-api.md); CI проверяет актуальность типов.
- [ ] Frontend демонстрирует экран на моках (список методов, одна схема).
- [ ] `demo-orders` ≈1000 строк, вывод детерминирован, ≥ 8 сценариев.
- [ ] Фикстуры scope разделов 1–4 готовы; бонусные — запланированы с владельцем.
- [ ] `verify_corpus.py` зелёный.
