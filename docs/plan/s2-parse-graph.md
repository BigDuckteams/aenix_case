# S2. Разбор Java и построение графа

**Часы:** H3–14 · **Трек:** A (engine) · **Веха:** M1 (вход) · **Требования:** FR-02, FR-03, FR-04

## Цель

Превратить Java-текст в семантическую модель, граф структуры и блок-схемы методов со стабильными ID и точными диапазонами. Покрыть весь обязательный и бонусный scope (record, enum, дженерики, лямбды, Stream).

## Зависимости

S0.7 (обёртка tree-sitter), S1.1 (схемы), S1.3/S1.6 (корпус).

Решения и отклонения:

- Модели engine (`engine/graph/model.py`) — dataclass'ы с теми же полями, что у схем API; тест сверяет наборы полей и валидирует графы схемами. Конвертация в API: `Model.model_validate(dataclasses.asdict(graph))`.
- Объекты `Node` tree-sitter нигде не хранятся, `start_point`/`end_point` не используются: см. [03 § 8](../03-tech-stack.md#8-фактические-версии-и-отклонения-итоги-s0).
- Ребро `exception` от `throw` идёт в ближайший подходящий `catch`: совпадение по имени типа, по иерархии типов проекта, `Exception`/`Throwable`, `RuntimeException` для типов `…Exception` вне проекта (кроме известных проверяемых). Точнее — после каталога JDK.
- Области видимости плоские (в пределах метода): при одноимённых переменных в соседних блоках побеждает последнее объявление. Для графа вызовов этого достаточно, правила анализа S7 потребуют настоящих областей.
- Фикстуры моков frontend теперь строятся настоящим движком (`scripts/gen_mock_fixtures.py`): `flows.json` содержит схемы всех методов `demo-orders`. Режим `--check` генератора раньше ничего не проверял (писал файлы); исправлено, тест `test_fixtures_are_up_to_date_with_generator` теперь действительно сверяет файлы.
- В `expected_kinds.json` девяти фикстур scope исправлены предположения, не совпавшие с кодом самих фикстур (например, `condition` там, где нет `if`).
