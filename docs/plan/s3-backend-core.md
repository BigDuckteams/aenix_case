# S3. Backend: проекты, версии, сборка, запуск

**Часы:** H6–16 · **Трек:** B (Backend/Runtime) · **Веха:** M1 · **Требования:** FR-01, FR-08, FR-09, FR-10, FR-19

## Цель

Дать frontend рабочий API: импорт проекта, версии и файлы, граф, сборка `javac`, запуск `java` с лимитами и потоком событий. Это основа, на которую ложатся правка (S5) и проверка поведения (S6).

## Зависимости

S0.2–S0.3, S1.1 (схемы). Эндпоинты графа подключаются к engine из S2 по мере готовности (до этого — заглушки на моках).

Решения по рантайму:

- Запуск синхронный и потоковый (`subprocess` + потоки чтения), а не `asyncio.create_subprocess_exec`: так он не зависит от политики цикла событий (на Windows `uvicorn --reload` использует селекторный цикл без подпроцессов). `RunManager` будет вызывать его через `asyncio.to_thread`.
- Целевой уровень `--release 21`; на более старом JDK берётся версия самого JDK. Проверено на JDK 17, на JDK 21 — в джобе `backend-jdk`.
- Тесты — `backend/tests/unit/test_runtime.py`: девять без JDK и десять с меткой `jdk` (кириллица во вводе, выводе и диагностиках, код выхода, исключение, таймаут, `while (true)`, лимит вывода, отмена, убийство потомков). Локально: `JB_JAVA_HOME=<путь к JDK> uv run pytest tests/unit/test_runtime.py`.

## Критерии выхода

- [ ] Импорт `demo-orders` любым способом ≤ 2 с; `main`-класс определён.
- [ ] `javac` собирает версию; ошибки с позицией; повторная сборка с тем же хешем мгновенная. (Сборка и кеш готовы на уровне движка, эндпоинта ещё нет.)
- [ ] `java` запускает программу с кириллицей во вводе и выводе; таймаут и лимиты работают; дерево процессов убивается (проверено на Windows и в Docker). (Проверено на Windows и JDK 17; Docker — нет.)
- [ ] SSE: события `log`, `result`, `done`; поздний подписчик получает replay.
- [ ] Версии: undo/redo, restore, diff; экспорт zip компилируется `javac`.
- [ ] Эндпоинты графа отвечают на `demo-orders` (на реальном engine либо на фикстурах с отметкой в README).
