# S4. Frontend: рабочая область и граф

**Часы:** H10–24 · **Трек:** C (Frontend) · **Веха:** M1 · **Требования:** FR-01, FR-03, FR-04, FR-05, FR-10

## Цель

Собрать интерфейс по концепт-макету: шапка, дерево проекта и палитра, холст графа, редактор кода, консоль, панели результатов. Показать на холсте блок-схемы (в том числе контейнеры циклов и ветки Да/Нет), связать их с кодом в обе стороны **для чтения** (правка — S5).

## Зависимости

S0.4–S0.5, S1.2 (моки). Реальные эндпоинты S3 подключаются по мере готовности: сначала импорт и дерево, затем граф и запуск.

## Задачи

| ID | Задача | Ч | Результат |
|---|---|---|---|
| S4.1 | Каркас рабочей области ([09 § 1](../09-frontend.md#1-раскладка-по-макету)): шапка (5 кнопок, индикатор версии, статус поведения), `ResizablePanelGroup` с левой колонкой, центром, правой колонкой и тремя нижними панелями; сохранение размеров в `localStorage`; токены цвета блоков (CSS-переменные) | 2 | Раскладка совпадает с макетом |
| S4.2 | Экран `/`: список проектов, диалог импорта (dropzone `.java`/`.zip`, вставка текста, встроенные примеры); переход в `/projects/[id]`; обработка ошибок (zod/ошибки API → тосты) | 1,5 | FR-01 на UI |
| S4.3 | Дерево «Проект» (пакеты → файлы → типы → члены), иконки, бейдж находок и сложности (зарезервировано под S7), контекстное меню (заглушки действий), вкладки центра (методы/файлы + «Структура») | 2 | Клик по методу открывает вкладку со схемой |
| S4.4 | Панель «Код Java»: Monaco (`next/dynamic`, `ssr: false`), подсветка Java, декорации узла, маркеры (ошибки разбора/компиляции), `revealRange`, режим только чтения до S5.1 | 1,5 | Код файла отображается, диапазоны подсвечиваются |
| S4.5 | **Холст графа** — часть 1: адаптер `FlowGraph → React Flow`, раскладка ELK в Web Worker (layered, вниз), кастомные узлы по `kind` (Метод, Переменная, Присваивание, Операция, Условие, Switch, Возврат, Throw, Break/Continue, Код), рёбра (`next`, подписи Да/Нет, `case`), масштаб `−/+/100%`, «вписать», мини-карта | 3 | Линейные и ветвящиеся схемы корректно рисуются на моках и на `demo-orders` |
| S4.6 | **Холст графа** — часть 2: контейнеры (циклы, `try`, `switch`, лямбда как карточка) с вложенной раскладкой ELK (`INCLUDE_CHILDREN`) и сворачиванием; блок вызова метода («внешний вызов») с жёлтым пунктиром и переходом в схему вызываемого; рёбра `back/break/continue/exception` | 2,5 | Схема `processOrders` из макета воспроизводится |
| S4.7 | Граф структуры: вкладка «Структура» (типы, методы, `extends/implements/calls`, режимы), переход к схеме метода | 1 | FR-03 на UI |
| S4.8 | **Синхронизация чтения** граф ↔ код: клик по узлу → Monaco подсвечивает диапазон; курсор в Monaco (дебаунс) → `locate` → выделение узла и панорама; URL-параметры `?file&method&node` | 1 | FR-05 |
| S4.9 | Консоль и запуск: панель «Консоль» (журнал сборки/запуска, stdout/stderr раздельными цветами, код выхода, время), диалог «Запуск» (stdin, args), хук `useRunEvents(runId)` на `EventSource`, кнопка отмены | 1,5 | FR-10 на UI, кириллица |
| S4.10 | Панели «Результат тестов» и правая «Анализ» — каркасы (пустые состояния), статус-бейдж поведения («? не проверено»); вкладки, фильтры-заглушки | 0,5 | Готовы к наполнению в S6 и S7 |
| S4.11 | Состояние: TanStack Query (ключи по `projectId/versionId`), Zustand (`workspaceStore`, `editorStore`), инвалидации; Vitest-тесты адаптера графа и хука SSE | 1 | Тесты зелёные |

Параллелизм: S4.1–S4.2 идут первыми (на моках). S4.5 стартует после S4.1; S4.6 — после S4.5. S4.3–S4.4 параллельно со S4.5.

## Артефакты

- `frontend/src/components/{workspace,graph,code}`, `stores/`, `workers/elk.worker.ts`.
- Vitest-тесты адаптера и SSE.

## Критерии выхода (веха M1, часть UI)

- [ ] Импорт `demo-orders` с главной страницы; дерево проекта открывается.
- [ ] Блок-схема метода `processOrders` содержит Да/Нет, контейнер цикла, внешний вызов; внешний вид сопоставим с макетом.
- [ ] Клик по блоку подсвечивает строки; курсор в коде выделяет блок (кириллица в строках не сдвигает подсветку).
- [ ] «Запуск» со stdin показывает вывод в консоли; кириллица корректна.
- [ ] Холст на 150 узлов остаётся отзывчивым (раскладка в Worker).
- [ ] E2E `demo_full_path` (до шага правки графа) проходит.
