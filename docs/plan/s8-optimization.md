# S8. Оптимизация

**Часы:** H30–40 · **Треки:** A (преобразования), B (gate, бенчмарк), C (UI) · **Веха:** M4 · **Требования:** FR-16, FR-15

## Цель

Превратить находки в безопасные автоисправления: предпросмотр, применение, quality gate (сборка + сценарии), пакетная оптимизация одной кнопкой и измеренный эффект («до 5.2×»).

## Зависимости

S7 (находки, чистота и инвариантность), S6 (gate, кандидаты, бенчмарк), S5 (правки текста), S4–S5 (UI).

## Задачи

| ID | Задача | Трек | Ч | Результат и тесты |
|---|---|---|---|---|
| S8.1 | **Инфраструктура преобразований** (`transform/base.py`): контракт `Transform`, предусловия (`Check`) на базе чистоты/инвариантности/алиасинга/независимости от порядка ([05 § 7](../05-analysis.md#7-инвариантность-и-чистота-для-безопасных-исправлений)), `propose`/`preview`/`apply`; создание версии-кандидата → gate → HEAD/отклонение; `accept`/`reject`; эндпоинты `fixes/*` | A + B | 3 | Тесты жизненного цикла: успех, провал gate, повтор |
| S8.2 | **Ядро OPT:** OPT-01 (индексация по ключу вместо вложенного поиска — пример слайда 5), OPT-02 (`contains` по списку → `HashSet`), OPT-03 (`StringBuilder` в цикле) | A | 4 | Тесты «до/после» + gate на `samples/optimizations/*`; негативные примеры (предусловия не выполнены) |
| S8.3 | Следующие OPT: OPT-04 (вынос сортировки), OPT-05 (инвариант в цикле), OPT-06 (`LinkedList` → `ArrayList`/`ArrayDeque`), OPT-07 (общее подвыражение) | A | 3,5 | Тесты «до/после», идемпотентность |
| S8.4 | **Расширение OPT:** OPT-08 (мемоизация чистой рекурсии), OPT-09 (`Map.merge`/`groupingBy`), OPT-10 (буферизация вывода), OPT-11 (перестановка этапов Stream), OPT-12 (обёртка → примитив) | A | 4 | Тесты; допускается после M4 (до M5) |

| S8.8 | **UI:** вкладка «Рекомендации» с предпросмотром (diff в Monaco, предусловия ✓/✗, эффект) и «Применить» со стадиями gate; диалог «Оптимизировать» (шаги с галочками → прогресс → отчёт); блок «Сложность: текущая → после»; блок «Оценка производительности»; результат gate (стадии, diff упавших) | C | 4 | E2E `optimize_all` |

## Артефакты

- `backend/engine/transform/*`, `samples/optimizations/*`.
- UI: предпросмотр, диалог оптимизации, отчёт «до/после».

## Критерии выхода

- [ ] Для PERF-находок ядра доступны исправления с предпросмотром, предусловиями и ожидаемым эффектом.
- [ ] После «Применить» версия становится HEAD только при зелёном gate; при красном — HEAD прежний, виден diff.
- [ ] «Оптимизировать» на `demo-orders`: сложность O(n²) → O(n)/O(n log n), все сценарии зелёные, ускорение измерено (≥ 2×).
- [ ] Пакет можно откатить одной кнопкой; каждый промежуточный HEAD — версия, прошедшая gate.
- [ ] Инвариант I8 зелёный на корпусе.
- [ ] Автоисправления не предлагаются, если предусловия не выполнены; причина показана.
